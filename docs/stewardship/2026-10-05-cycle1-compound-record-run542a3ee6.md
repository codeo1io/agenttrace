## Prevention rules (repo-durable, reuse verbatim)

- **PR-1 — disclosure belongs inside the function that owns the bail, not at the caller's empty branch.** `load_sessions_report` early-returns on empty sessions, so a `print_sessions_load_disclosure` call in `run()`'s empty branch is unreachable dead code for the shrink-to-zero case — exactly the most extreme silent degradation. Found this cycle by live probe after the adopted implement trail passed all its green-path tests. Rule: any `*_report` builder that can bail on empty must carry its own disclosure/telemetry at the bail, and the regression test must exercise the ALL-inputs-bad corpus (dir where every walk-admitted file fails), not only the healthy-plus-one-bad shape.
- **PR-2 — a swallowed failure must never be persisted as a success snapshot.** The sqlite lane cached `Vec::new()` results for stores that failed mid-query, making a poisoned store indistinguishable from an empty one *forever* (the cache would keep answering empty after the store healed or was inspected). Rule: on error paths skip the snapshot entirely; absence and failure stay distinguishable at every layer that caches.
- **PR-3 — stdout is a document; diagnostics ride stderr.** Held under the batch: `-f json` stdout parses as a pure JSON array with the disclosure note on stderr only (rm-301 purity lineage). Any new listing surface keeps this contract.
- **PR-4 — cap and name.** Hostile corpora must not flood the note: names are collected bounded (`UNPARSED_FILE_NAME_CAP = 64`) and rendered capped (6 per category with `(+N more)`), and every category names concrete files/stores, never just a count.
