## Durable lessons this cycle

1. **Spool scratch reaping is real mid-run, not hypothetical:** the roadmap phase's scratch dir and its /tmp mirror were both gone within ~15 h of emission; the typed envelope was the only surviving rider authority. Prevention: mirror band artifacts to `/home/agent/.cache/at-<phase>-<id>/` AT EMISSION (this run's implement/full_tests did; roadmap didn't).
2. **Rebuild authority = the typed envelope's rider list** (id + anchor + gist) — never fleet memory, never banner prose: wall-lineage divergence strikes inside one repo family too (rm-493/rm-248 exist as wall rows that simply carry no riders).
3. **Mid-turn provider deaths leave distinguishable trails:** boot-deaths (3-4 events, no scratch) vs real-work deaths (message_count 15+, scratch present, tree diff). Adoption recipe: identity lineage → round-trip (apply-check on pristine wall → cmp postimage → cmp worktree) → census → envelope cross-check → batch-integrity md5.
4. **-U1 rider patches are offset-fragile on diverged walls:** the single context line is row-generic, so fuzz folding can misanchor a rider into a neighbouring row. Always follow a fuzz fold with a placement census (rider must sit inside the span of the id it names).
5. **Stale row-note anchors rot after slices land** (stewardship corrected statusline.rs :303-311→:413 and main.rs :1113-1128→:833 by live re-read); **row notes also rot in the open-arm direction** — slice-2 was recorded open after it had landed. Re-read the full row AND the in-tree wiring before sizing a slice or pinning a contract.
6. **Verify prose against code before banking it:** the rider's Cf-set enumeration (U+00AD 'implemented') contradicted the very CHANGELOG the same cycle wrote; a one-grep check against statusline.rs:431-433 settled it.
