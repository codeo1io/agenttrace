**Prevention class:** single-source constants pinned in multiple places.

## The trap

`SESSION_CACHE_SCHEMA_VERSION` is a single constant in `crates/agenttrace-core/src/session_cache.rs:8`, but its value is depended on in **six** places that break differently when the constant bumps:

1. `crates/agenttrace-core/src/session_cache.rs:8` — the constant itself (the bump).
2. `crates/agenttrace-core/tests/discovery_contract.rs:1056` — inside `rust_writes_and_reuses_go_compatible_session_cache` (fn at `:1003`): the cache-hit contract pin. Reads the **exported constant dynamically** (the rm-538 landing moved both discovery pins off literals), so it cannot drift numerically — it goes red when the write/read regeneration contract itself regresses.
3. `crates/agenttrace-core/tests/discovery_contract.rs:1229` — inside `rust_refreshes_cache_entries_from_old_schema_version` (fn at `:1189`): the stale-schema sweep pin. Also dynamic; its planted fixture (`:1202`) carries an ancient `schema_version` and the test asserts regeneration to the live constant, so it stays adversarial at every bump.
4. `crates/agenttrace-tui/src/tests.rs` — the planted-cache fixture in `ctrl_r_force_reload_clears_session_cache_before_loading`: planted at the **current** number by interpolating the exported `agenttrace_core::SESSION_CACHE_SCHEMA_VERSION` into the hand-written JSON (the rm-520/rm-521 landing moved it off a hand-pinned literal so it cannot rot on a bump), and the test asserts a **warm hit** (`cache_hits == 1`). Reintroduce a stale literal here and the planted entry looks stale — the warm-hit assertions go red in `cargo test -p agenttrace-tui`.
5. `docs/guides/governance-reports.md` — a prose sentence carrying the number ("The session cache is schema 53 …"), which `scripts/ci/check-docs-commands.sh` verifies against the **live constant** by running the release binary.
6. `crates/agenttrace-core/tests/usage_occurrence_contract.rs` — `warm_cache_replays_cold_disclosure_and_schema_53_invalidates_v32` (added with the rm-710 oracle at the run-73fe8e1e landing) carries the number in **three** places on purpose: the fn name, the `assert_eq!(SESSION_CACHE_SCHEMA_VERSION, 53, …)` pin, and its message. Unlike the dynamic pins this one is *intentionally literal* — it goes red at EVERY bump so the sweep cannot be forgotten; sweep all three together (and keep the degraded-fixture leg's `schema_version: 32` planted value below the live constant).

Miss any one of the literal-bearing sites and the failure appears at a *later* gate than your edit: the tui fixture only in `cargo test -p agenttrace-tui`, and the governance sentence only in the CI docs gate against a release build — i.e. possibly after you already declared the phase green on focused tests. (The two discovery pins fail only on semantics regressions, not on the bump itself — which is exactly why the literal sites must be swept by hand.)

## The rule

When a parser-semantics change bumps the schema (the rm-230 convention: cached sessions must regenerate under corrected totals):

1. Bump the constant in `session_cache.rs`.
2. In the same change, sweep every dependent site: both `discovery_contract.rs` pins (confirm they still read the exported constant, not a reintroduced literal), the `tests.rs` planted-cache fixture number, and the `docs/guides/governance-reports.md` sentence.
3. Verify the docs sentence against the **live** constant via the docs gate with a private `AGENTTRACE_CI_OUT` (never the shared default path — see the gate's environment notes), not by eyeballing the markdown.
4. Land every dated pin-note in the same commit as the bump — a site updated in a later commit leaves a window where the suite is red on `origin/master` for anyone between the two commits.

## Why five sites and not one

The pins are deliberate adversarial coverage: each one fails for a different regression (stale cache accepted, cache-hit regressed, planted cache trusted across a semantics change, docs drifting from code). The cost is this checklist — which is cheaper than any of the regressions it catches. Cite the test **names**, not just line numbers, when recording a sweep: anchors drift at every integration, and this file was re-anchored once already for exactly that reason.
